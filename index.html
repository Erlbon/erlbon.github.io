Bulk Metadata Editing for Media Files

Metadata are the things you normally never see, but always need. If they can be written into the file, they're always there when you need them, so you don't have to rely on scraping them from somewhere else. These tools were created to help you see, correct, and update whatever information is written into your media files.

The ƆBZ Redactor

Edit ComicInfo.xml metadata in CBZ comic archives — title, series, credits, and more — plus lookups against Comic Vine, the Grand Comics Database, and Bedetheque or your own offline GCD and ComicRack databases, spotting and shrinking oversized scans, CBR/CBT/CB7 conversion, duplicate finding, and a one-click Redact.

The ƎPUB Redactor

Bulk-edit EPUB ebook metadata for Kobo and other e-readers, with Google Books / Open Library lookups (online, or from a local Open Library database you build), Clean Up Authors, duplicate finding, cover generation, Table of Contents generation, and format conversion via Calibre.

The ɯP3 Redactor

Check MP3 file integrity, detect BPM and musical key, measure loudness, look albums up on MusicBrainz (online, or from a local database you build) and Discogs, find duplicate tracks, and bulk-edit tags across a whole library at once.

The Ʌideo Redactor

Bulk-edit MKV/MP4 metadata with TMDB lookups, offline lookups in a local IMDb database you build, season/episode matching, subtitle fetching, file checks and repair, duplicate finding, and poster art — for movies, TV, and everything in between.

Why these exist

Embedded metadata is growing more and more important, but there are very few programs available to the private consumer to make these changes on a larger file set.

Following the same editing principles as Mp3tag (Florian Heidenreich, 1999), this suite of tools allows you to change:

  • Comics
  • Books
  • Videos
  • Music in addition to Mp3tag, not as a replacement for it

They all share the redactor_common repo for a unified appearance and functionality. There are enough format-specific differences to keep them as four separate apps rather than one big one.

What all four share

Because they share redactor_common, the same things work the same way in every app:

  • Redact: one click runs an editable recipe on the selected files. Each changed file is saved in place and its original goes to the Recycle Bin. Guesses are applied only above a confidence threshold; the rest is listed under Needs review.
  • Move into folders in Rename / Export / Move, under a library root, with undo; and metadata from the folder path, the same kind of pattern read in reverse.
  • Export / Import Settings to carry your setup to another computer. Secrets are never included.
  • Preferences (Tools > Preferences, Ctrl+,): one shared dialog for the everyday settings, with OK / Cancel / Apply and Reset to Defaults per page. Settings keep their old places, so Export / Import Settings is unaffected.
  • Find Duplicates: in the ƎPUB (Repair menu), ɯP3 (Analyze menu) and Ʌideo (Media menu) Redactors it opens the same review dialog, which shows how strong each match is and why, selects nothing for you, remembers groups you mark “Not duplicates”, and never trashes every file of a group. The ƆBZ Redactor has its own duplicate finder, matching comics by their pages.
  • Command palette (Ctrl+K), one standard menu layout (File, Edit, View, the app’s own menus, Tools, Help), Open in Default App, and Ctrl+S to save every changed file.
  • Keys and tokens in the credential store: where an app uses an online service key (Comic Vine and GCD in the ƆBZ Redactor; TMDB, TheTVDB and OpenSubtitles in the Ʌideo Redactor; a Discogs token in the ɯP3 Redactor), it is stored in your operating system’s credential store, not in a settings file.
  • Safe in-place saves: a file is replaced only after the new copy is written and verified, so a failed save never loses the original.
  • Windows and Linux: every release has a standalone .exe and a self-contained Linux download, and the tests run on Linux as part of each release build.

Sources at a glance

None of the four apps needs an outside source to edit, check or convert files. Where an app can look metadata up, it does so in three ways: from an online service, from a local database built from files you download yourself, or from the file itself (its name, folder, tags or text). Nothing is bundled and nothing is downloaded automatically; online sources are asked only when you run a lookup. Where a service needs a key or token, you register for it yourself and the app keeps it in your operating system’s credential store. Each app’s page has the full detail under “Where the metadata comes from”.
